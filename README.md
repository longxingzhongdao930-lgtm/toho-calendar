# TOHO Calendar

東邦音楽大学の学生向け非公式予定管理アプリ。音楽と、毎日のリズム。

Next.js 16 / React 19 / TypeScript / Tailwind CSS 4。バックエンド・APIキー・有料サービス不要の静的サイトです。大学が提供・運営するサービスではありません。

## 開発

Node.js 24、npm を使用します。

```sh
npm ci
npm run dev
```

開発サーバーはポート3000で起動します。

```sh
npm run typecheck
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

既存の Chromium を使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e`。E2EはPCとiPhone 15 Pro Max相当の画面サイズで実行します（モバイルはChromiumによるエミュレーションで、実機Safariではありません）。本番成果物は `out/` です。静的exportのため `next start` ではなく `python3 -m http.server 3000 --directory out` 等で配信してください。

## 機能

- ホーム：今日、次の予定、今週、公式学年暦のお知らせ
- カレンダー：月・週・日、種類別色分け、日付選択と予定詳細
- 一覧：日付順、予定名・会場・メモ検索、カテゴリ絞り込み
- オケ：通常練習・臨時練習・分奏・本番、会場の登録と絞り込み
- 授業・試験：平常授業・休講・補講・試験期間など種類を自由入力
- 個人予定：新規追加・編集・削除、終日、期間、時刻、重要マーク。弦楽器レッスン・弦楽器合わせ・伴奏合わせ・室内楽合わせ・弦楽合奏・個人練習の追加ボタンと種類別絞り込み。日時は本人が指定して保存し、公開データには含めません。
- 毎週・毎月の繰り返し（終了日設定可）、ライト／ダーク
- JSON書き出し・検証付き読み込み（追加・置換を選択）

PCでは左ナビ、スマホでは下部ナビを使います。スマホのオケ・授業画面は左上メニューから開けます。キーボード操作・フォーカス表示・モーダルのフォーカス制御・動きを抑えるOS設定に対応します。

## 初期データと出典

ユーザー提供の**2026年度公式学年暦のスクリーンショット4枚**を一次資料として、2026年4月〜2027年3月の日程を `lib/academic.ts` に登録しました。日付・名称が読めた項目のみ「公式資料確認済み」、読めない細字・条件は「要確認」です。曜日別回数表は授業・試験画面から閲覧でき、数字を判読できた42日分だけ数値を表示します。未読の回数は推定していません。

[抽出範囲・訂正・移行仕様](docs/academic-data.md) と [参照先の公式PDF](https://www.toho-music.ac.jp/wp-content/uploads/2026/04/2026_college_calendar.pdf)。PDF本文の直接取得は通信制限で未実施です。スクリーンショット自体は一切公開せず、抽出データのみ使用します。個人予定の初期配布も外し、既存端末にある個人予定は保持します。

主な訂正：**ウインド定期演奏会は12/13→12/12**、後期の**学科目まとめ期間は1/15・16、1/18〜21**。12/8〜11・12/23の「学科目補講可能」を全授業休講とは断定しない表示に変更しました。

初回のみデモデータを登録します。空のバックアップを復元した場合も、再読込で初期データを再登録しません。

## 保存・バックアップ仕様

予定は `localStorage` の `toho-calendar-v1` に保存します。同じ端末・ブラウザ・オリジン内で利用でき、クラウド同期はしません。端末やブラウザの削除・プライベートブラウズ終了等で消える場合があるため、設定から定期的にJSONを書き出してください。サーバーに予定を送る処理はありません。複数タブでの同時編集は避けてください（最後の保存が優先）。

- JSON形式：`{ "version": 1, "events": [...] }`。最大5MB・5,000予定。読み込みは追加・全置換を選択でき、破損・不正日付・重複IDを拒否します。
- 読み込みに失敗した既存データは自動上書きしません。正常なJSONの復元で保存を再開できます。
- 繰り返しの編集・削除はシリーズ全体に適用。複数日の繰り返し、単発の例外変更は未対応です。毎月31日は31日のある月のみ表示。
- 一覧はシリーズごとの開始日順。カレンダーは各発生日で表示。次の予定は今後365日、ホームのカテゴリ別の次回は180日から探します。
- データは暗号化しません。共有端末に機密情報を登録しないでください。バックアップにも予定が含まれるため公開リポジトリに追加しないでください。

## 無料公開

### GitHub Pages

1. リポジトリの **Settings → Pages → Build and deployment → Source: GitHub Actions** を選択します。
2. `main` へpushするか、Actionsの **Deploy GitHub Pages → Run workflow** を実行します。
3. Actionsに表示される公開URLを開きます。

ワークフローは `NEXT_PUBLIC_BASE_PATH=/toho-calendar` を指定して `out/` を公開します。リポジトリ名を変更した場合は `.github/workflows/pages.yml` のパスも変更してください。Pages用のローカルビルドも `NEXT_PUBLIC_BASE_PATH=/toho-calendar npm run build` で確認できます。設定した `basePath` はビルド時に固定されます。

### Vercel

リポジトリをImportし、FrameworkをNext.js、Install Commandを `npm ci`、Build Commandを `npm run build` とします。Node.jsは24系、`NEXT_PUBLIC_BASE_PATH` は設定しないでください。サーバー機能・データベース・環境変数・APIキーは不要です。無料プランの利用条件内で運用できます。

## 構成

`app/` は画面とスタイル、`components/calendar-app.tsx` はクライアントUI、`lib/calendar.ts` は日付・繰り返し・検証、`lib/academic.ts` は年度日程と回数の転記、`lib/seed.ts` は初期化・既存データ移行、`tests/` はユニットとブラウザテストです。GitHub Actionsで型チェック・ユニット・ビルド・E2Eを実行します。

## iPhone・PWA・オフライン

- アプリ名は **TOHO Calendar**。ホームに今日・次の予定・月間カレンダーを表示し、430×932 CSSピクセル（iPhone 15 Pro Max相当）・セーフエリア・文字入力16pxに対応します。
- アプリ全体に「非公式の学生向けカレンダー」を表示。Apple touch icon、192/512pxアイコン、standalone表示、iPhone 15 Pro Max縦向けの起動画面を設定済みです。起動画面・インストールの最終表示はiOSバージョンに依存します。
- HTTPSの公開URLを**Safari**で開き、共有 → **ホーム画面に追加** → **追加**。初回はオンラインで「オフライン閲覧の準備完了」が表示されるまで待ってください。
- 起動シェルと同一オリジンの静的アセットだけをService Workerで保存。予定データはlocalStorageのみで、外部への送信、アクセス解析、広告、API呼び出しはありません。オフラインでも再起動・保存済み予定の閲覧と編集・JSON書き出しができます。公式PDFへのリンクはオンライン時に利用してください。
- Service Workerは**本番ビルドだけ**で登録します。初回アクセス前のオフライン利用や、iOSがキャッシュ・端末保存領域を削除した場合の保持は保証できません。JSONを定期的に書き出してください。Safariとホーム画面アプリで保存領域が分かれる場合は、JSONで移行してください。公開先の変更でも保存領域は別になります。
- 本番ビルドの `postbuild` が `out/sw.js` と静的アセット一覧を生成します。`out/` 全体を配信してください。Service Workerを含めてHTML・CSS・JSを同じ公開先に配置する必要があります。
- オフラインテスト：`npm run build` のあと `npm run test:pwa`。静的成果物を配信し、初回ロード→オフライン→再読込→個人予定の保存→再起動→JSON書き出しを検証します。ブラウザはChromiumのiPhone相当エミュレーションです。実機Safariでの最終確認は別途必要です。

### Vercelへの接続（認証する本人の操作が必要）

1. [Vercelの新規プロジェクト画面](https://vercel.com/new) でGitHubアカウントを接続します。
2. `longxingzhongdao930-lgtm/toho-calendar` をImportし、Production Branchを `main` にします。
3. Buildは `npm run build`、Outputは `out`（`vercel.json` に指定済み）。`NEXT_PUBLIC_BASE_PATH` は設定しません。APIキー・データベースは不要です。
4. Deploy後、Vercelが発行する実際の `https://…vercel.app` をSafariで開き、上記の手順で追加します。以後mainへのpushで自動更新されます。

この制作環境ではVercelのアカウント認証がなく、`api.vercel.com` への通信も403で拒否されます。そのためVercel接続・URL発行・公開先の実機Safari検証は未実施です。未発行のURLを推測して公開済みと案内しません。

個人・学内資料は公開初期データと分離し、JSONで本人の端末だけに追加できます。設定 → JSONを読み込む → **既存の予定を残して追加**。同じIDは更新、同じ内容は重複させず、全置換も従来どおり選択できます。取り込んだ個人資料の内容は公開サイトやGitHubに送信しません。繰り返し予定には「実施しない日」を指定でき、休講日・長期休業などを除外できます。

ファイル保存ができない端末では、予定をURLのフラグメント（`#toho-import=`）にgzip＋base64urlで収めた個人用取込リンクも利用できます。内容はブラウザ内で解凍・検証し、確認後に追加します。フラグメントはHTTPリクエストに含まれず、読み取り直後にアドレスから除去します。リンク自体には個人予定が含まれるため、公開・共有する際は通常のサイトURLを使ってください。対応は `DecompressionStream` が使える現行Safari等。展開後5MB・圧縮URL部分50,000文字以内に制限し、不正リンクでは既存データを変更しません。個人用ペイロードをリポジトリや静的配信物へ含めないでください。

Safariへ移動したら予定が見えなくなる場合、ChatGPT内ブラウザとの保存領域の違いが考えられます。**予定が見える元のブラウザ**で設定 → **Safariへ引き継ぐ準備**。この操作で現在の個人予定を含むリンクを作り、現在のURLにも設定するため、そのままメニューの「Safariで開く」で渡せます。自動でSafariを起動する機能ではありません。メニューがなければ **引き継ぎリンクをコピー** → Safariのアドレス欄へ貼り付け → 追加。ホーム画面アプリへは、アプリの設定内の貼り付け欄でも取り込めます。コピーできない環境では表示欄を長押しして全体をコピーしてください。元の予定は削除せず、移行先でも追加前の確認を行います。生成中のURLには個人予定が含まれるため、そのリンクを他人と共有しないでください。
